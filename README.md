# 업무망 무단 장비 점검기 (Scan_Phone_Network)

학교 **업무망**에 무단으로 연결된 장비를 자동으로 찾아내는 도구입니다.

- 🔴 전화업자가 스위치/방화벽에 꽂은 **공유기(NAT 라우터)**
- 🔴 교사가 무단 설치한 **무선 AP**
- 🟡 미등록 **인터넷 전화기(VoIP)**

비전문가 교사도 더블클릭 한 번으로 점검할 수 있는 **GUI 앱**이며,
정보부장 PC에 두면 **백그라운드에서 망을 상시 감시**하고 새 무단 장비가 나타나면 경고합니다.

## 탐지 원리

### 능동 — 대역을 훑어서 찾기

| 신호 | 무엇을 잡나 |
|------|------------|
| MAC OUI 조회 | 제조사로 구분 (ipTIME·DAVOLINK=공유기 / Yealink=전화기 / SECUI·Ubiquoss=정상 인프라) |
| ICMP 핑 스윕 + TTL | 살아있는 호스트 + NAT 뒤 추가 홉 |
| DHCP 서버 탐지 | 무단 공유기가 자체 DHCP 응답 → **결정적 증거** |
| SIP OPTIONS (5060) | 전화기 모델/벤더 |
| NetBIOS 이름(137) 대조 | 같은 PC 이름을 여러 장비가 사용(복제 설치) → ⚠ 이름중복 |
| HTTP 배너/타이틀 (80/443) | 공유기 로그인·전화기 관리 페이지 |
| SSDP/UPnP (UDP 1900) | 공유기의 `InternetGatewayDevice` 광고 |
| SNMP `sysDescr` (161) | 프린터·복합기 모델명 |

> **SSDP 에 너무 기대지 마세요.** 실제 학교 업무망 점검에서 SSDP 로 잡힌 공유기는
> **0건**이었습니다(응답한 건 프린터 1대뿐). 요즘 공유기는 UPnP 가 기본으로 꺼져 있고,
> 무단 설치한 사람이 관리 기능을 꺼 두는 경우도 많습니다.

### 수동 — 듣기만 해서 찾기

**핑 스윕은 구조적으로 못 찾는 장비가 있습니다.** 그래서 스캔과 동시에 듣기도 합니다.

| 신호 | 무엇을 잡나 |
|------|------------|
| DHCP DISCOVER (67) | **IP 가 아예 없는 장비.** 주소를 못 받아 조르기만 하는 공유기는 핑에 절대 안 잡힌다. 요청 안의 MAC 으로 제조사를 판정한다 |
| DHCP OFFER (68) | 이 망에 있으면 안 되는 DHCP 응답. `192.168.137.x` 면 **윈도우 PC 의 모바일 핫스팟** |
| mDNS (5353) | 장비 이름과 종류. `_googlecast` 는 유선 업무망에 있으면 안 되는 신호 |
| **ARP (관리자 권한)** | **다른 대역을 쓰는 장비.** mDNS·SSDP 는 그걸 쓰는 기기만 말하지만 ARP 는 통신하는 모든 기기가 쓴다 |

> 실측 비교 — 같은 자리, 같은 시간:
> **기본 점검(UDP 청취) 30초 → 남의 대역 1개 / 정밀 점검(ARP) 120초 → 10개 이상.**
> 관리자 권한 없이 돌리면 "안 나왔다"를 "없다"로 읽으면 안 됩니다.

여러 신호를 합쳐 **종류 + 신뢰도(0~100%)** 로 판정합니다.

### 망 분리 판정

이 앱의 결론은 장비 목록이 아니라 두 줄입니다. **무단 공유기가 있는가, 다른 망과 분리돼 있는가.**

판정 근거는 단순합니다. **분리돼 있다면 업무망 자리에서는 업무망 주소만 들려야 합니다.**
남의 대역 주소가 들린다면 그 망은 같은 브로드캐스트 도메인에 올라와 있다는 뜻이고, 그게 곧 분리 실패입니다.

혼선이 어디서 들어오는지도 짚습니다. MAC 앞 5바이트가 같고 끝자리만 다른 장비가
서로 다른 대역에 나타나면 한 섀시의 두 인터페이스이며, **그 장비가 두 망을 물고 있는 것**입니다.

## 프로젝트 구조

```
Scan_Phone_Network.sln
└─ src/
   ├─ Core/   ScanPhoneNetwork.Core   엔진(스캔·프로브·분류·CSV) — net8.0
   ├─ Gui/    ScanPhoneNetwork.Gui    Avalonia 화면 + 감시 + 트레이 — net8.0
   └─ Cli/    ScanPhoneNetwork.Cli    명령줄 버전(테스트·헤드리스) — net8.0
```

> GUI는 **Avalonia UI**라 **리눅스에서 개발·실행하고 Windows exe로 배포**합니다(전 프로젝트 OS 무관).

## 빌드

```bash
# 전체 빌드 (Linux/Windows 공통)
dotnet build -c Release

# GUI 실행해 보기
dotnet run --project src/Gui

# 배포용 Windows 단일 실행파일(.NET 런타임 포함)
dotnet publish src/Gui/ScanPhoneNetwork.Gui.csproj -c Release -r win-x64 --self-contained
# 결과: src/Gui/bin/Release/net8.0/win-x64/publish/업무망점검기.exe
```

## 사용법

### GUI
1. `업무망점검기.exe` 더블클릭
2. (선택) **대상 대역**에 `10.20.30.0/24` 입력 — 비우면 PC 대역 자동
3. **스캔 시작** → 결과 표에서 빨간 행 = 의심 장비
4. **CSV 저장** → 교육청 보고/대장용
5. 의심 장비가 정상이면 우클릭 → **정상(승인) 등록**

### 감시 모드 (정보부장 PC)
1. **감시 모드** 체크 + 주기(분) 설정
2. **윈도우 시작 시 자동 실행** 체크 → 로그인 시 트레이에서 자동 감시
3. 승인 목록에 없는 새 의심 장비 발견 시 트레이 알림 + 경고음

### CLI (테스트용)
```bash
scan-phone-network 10.20.30.0/24 --csv result.csv
scan-phone-network --oui oui.csv          # 제조사 DB 확장
```

## 제조사 식별

**따로 할 일이 없습니다.** 앱이 처음 실행될 때 IEEE 공식 OUI 목록(약 4만 건)을
자동으로 받아 `%LOCALAPPDATA%\ScanPhoneNetwork\oui.csv` 에 캐시합니다(1년마다 갱신).

- 폐쇄망이라 못 받으면 내장 목록만으로 동작하고, 보고서에 그 사실을 표시합니다.
- 파일을 직접 주려면 `--oui <경로>` 또는 exe 옆에 `oui.csv` 를 두면 됩니다.
- 다운로드 주소: https://standards-oui.ieee.org/oui/oui.csv

> 이게 왜 중요한가 — 내장 목록만 쓰면 실측에서 다른 대역 장비 대부분이
> "제조사 미상"으로 나왔습니다. 제조사를 모르면 그게 공유기인지 전화기인지
> 판단할 수가 없어 보고서가 무용지물이 됩니다.

## 스위치 포트까지 찾기 (선택)

`--snmp <community>` 를 주면 스위치의 MAC 주소 테이블을 읽어
**문제 장비가 몇 번 포트에 물려 있는지**까지 보고합니다.

```powershell
scan-phone-network.exe --snmp public
```

읽기 전용 community 면 충분합니다. 스위치에 SNMP 가 꺼져 있거나 community 가
다르면 이 단계만 건너뛰고 나머지는 그대로 보고합니다.

> 스위치를 교육청·유지보수 업체가 관리한다면 community 를 받아야 합니다.
> **"어느 포트에 꽂혀 있나"에 답할 수 있는 방법은 이것뿐입니다.**

## 권한 참고

앱은 **관리자 권한 없이도 그대로 돌아갑니다.** 다만 볼 수 있는 범위가 달라집니다.

| | 일반 권한 (기본 점검) | 관리자 권한 (정밀 점검) |
|---|---|---|
| 핑 스윕·포트·배너·SSDP·SNMP | ○ | ○ |
| mDNS·DHCP 수동 청취 | ○ | ○ |
| **ARP 수집** | ✕ | **○** |
| 다른 대역 탐지 폭 | 남의 대역 1개 | **10개 이상** |

윈도우 raw socket 은 IP 계층만 보여줘서 **ARP 를 볼 수 없습니다.** 그래서 ARP 수집은
윈도우 기본 탑재 도구인 `pktmon` 을 쓰고, 이게 관리자 권한을 요구합니다.
(교사 PC 마다 Npcap 같은 드라이버를 깔지 않아도 되도록 이 방식을 골랐습니다.)

권한이 없으면 조용히 건너뛰고 나머지 결과만 보고하며, 보고서 맨 아래
**「점검 깊이」** 에 어느 쪽으로 돌았는지 표시합니다.

> 일반 권한으로 돌려 아무것도 안 나왔다면, 그건 **"없다"가 아니라 "이 방법으로는 안 보인다"** 입니다.

`--selftest` 로 망을 건드리지 않고 판정·보고 로직만 확인할 수 있습니다.
